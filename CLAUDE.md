## Project overview

Batch ETL pipeline for NYC TLC Yellow Taxi trip data, built as a learning project /
portfolio piece. Medallion architecture (Bronze → Silver → Gold), implemented with:

- **DuckDB** as both the compute engine and the local warehouse
- **dbt (dbt-duckdb)** for transforms/modeling/testing (Silver + Gold layers)
- **Airflow (LocalExecutor)** for orchestration (download → load → transform → test)

No Spark/BigQuery/dashboard — intentionally out of scope for now.

README.md is in Vietnamese and is the source of truth for project goals/status; keep
it in sync with major milestones if asked to update progress.

## Architecture

```
NYC TLC (Parquet files)
        │  download
        ▼
   Bronze layer        raw data, untouched
        │  dbt (staging models)
        ▼
   Silver layer        typed, renamed columns, junk rows filtered
        │  dbt (marts models)
        ▼
   Gold layer           star schema
```

Each layer is a separate DuckDB table/model — nothing is overwritten in place, so
transforms can be re-run and traced without re-downloading data.

## Key conventions

- `data/raw/` and `data/staging/` are gitignored (regenerated by ingestion scripts /
  transforms); only `.gitkeep` is tracked. Never assume Parquet files there are
  committed — they're local artifacts.
- `ingestion/download_tlc.py` downloads are skip-if-exists (idempotent by filename),
  not content-hash based.
- On Windows, stdout is reconfigured to UTF-8 in scripts that print DuckDB's
  `.show()` output, since box-drawing characters crash under legacy cp1252 consoles
  — keep this pattern in any new script that prints DuckDB tables.
- Code comments and docstrings in this repo are written in Vietnamese explaining the
  *why* (e.g. rationale for streaming downloads, what data profiling is for);
  match this style/language when extending existing files rather than switching to
  English mid-file.
